## 🛠️ خارطة الطريق (4 مراحل)

### المرحلة 0 — إصلاح كسر الثقة 🔥 (يوم–يومين | أولوية قصوى)
> الهدف: إيقاف النزيف فوراً قبل أي تطوير.

1. **إصلاح المايك الوهمي** — حلين:
   - **(أ) حقيقي:** إضافة `record` + `speech_to_text` + `permission_handler` → تسجيل حقيقي + تحويل صوت لنص عربي.
   - **(ب) مؤقت:** إخفاء زرار المايك لحد ما يتعمل حقيقي — **ممنوع يفضل وهمي.**
2. **ربط كل الردود السريعة بـ handlers فعلية** — جدول intents مقصودة، وكل رد سريع يتحول لإجراء: "تواصل مع الفني" → اتصال/WhatsApp بالفني، "اتصل بنا" → `url_launcher`، "طلب فني طوارئ" → فتح شاشة الطلب بـ `isEmergency: true` + نتيجة `smart-match`.
3. **إزالة كل الثوابت** — المدينة من `userLocationProvider`، رسوم الزيارة من أرخص فني متاح فعلاً، أوقات الاستجابة من بيانات فعلية.
4. **زمّ أزرار مش بتشتغل** — أي quick reply مش له handler يتشال من القائمة.
5. **زرار إعادة الإرسال** عند فشل الاتصال بالـ Edge Function.

### المرحلة 1 — Backend: محادثة متصلة بقاعدة البيانات 🗄️ (أسبوع)

**جداول جديدة (SQL):**
```sql
-- 1) جلسات المحادثة (للعميل)
create table chat_sessions (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references auth.users not null,
  title text,                    -- أول سؤال للعميل كعنوان
  created_at timestamptz default now(),
  last_message_at timestamptz
);

-- 2) الرسائل
create table chat_messages (
  id bigint generated always as identity primary key,
  session_id uuid references chat_sessions on delete cascade not null,
  role text check (role in ('user','assistant','tool')) not null,
  content text not null,
  image_url text,
  intent text,                   -- اللي اكتشفناه (للتحليلات)
  diagnosis jsonb,               -- نتيجة التشخيص لو موجودة
  feedback smallint,             -- 👍👎 من العميل
  tokens int,
  created_at timestamptz default now()
);
create index on chat_messages (session_id, created_at);
create index on chat_messages (intent, created_at);  -- للتحليلات

-- 3) قاعدة معرفة للأسعار والأسئلة الشائعة (RAG لاحقاً)
create table knowledge_base (
  id bigint generated always as identity primary key,
  category text,                 -- pricing | faq | safety | policy
  question text, content text,
  embedding vector(768),         -- لاحقاً للبحث الدلالي
  updated_at timestamptz default now()
);
```

**Edge Function جديدة `agent-chat` (تستبدل `analyze-problem` تدريجياً):**
- المدخلات: `session_id` + `messages[]` (آخر 10-15 رسالة) + `context` (اسم العميل، مدينته، طلباته النشطة بأكوادها، الفنيون المتاحون في منطقته).
- المخرجات: JSON موحد `{ reply, intent, actions[], diagnosis? }` بدل نية منفصلة عند العميل — **الـ AI هو اللي يحدد النية، مش regex**.
- **تسجيل كل تفاعل** في `chat_messages` + تسجيل `fallback_rate` ومدة الاستجابة.
- رفع الصورة لـ Storage (`chat-images/{user_id}/{uuid}.jpg`) وتمرير URL للنموذج البصري.

### المرحلة 2 — Agent حقيقي متعدد الخطوات 🤖 (أسبوع–أسبوعين)

1. **ذاكرة محادثة كاملة** — تحميل آخر 15 رسالة في كل طلب + ملخص جلسة طويلة.
2. **Tool Calling** — النموذج يقدر ينفذ أدوات فعلية (تُنفذ في الـ Edge Function وليس عند العميل):
   - `get_active_orders(user_id)` / `track_order(code)` / `get_tech_location(order_id)`
   - `check_warranty(order_id)`
   - `get_pricing(service_type, city)`
   - `get_available_technicians(service, area)`
   - `create_request(...)` / `create_emergency_request(...)`
3. **Flow أسئلة المتابعة** — لو `confidence < 0.55` يسأل سؤال واحد ذكي، يخزّن الإجابة (`FollowUpAnswer`) ويعيد التحليل بسياق أغنى (باستخدام نفس الـ `answers[]` الموجودة في العقد).
4. **طوارئ فعلية** — intent طوارئ → رد فوري بخطوات السلامة + `create_emergency_request` + إشعار push/WhatsApp لأقرب 3 فنيين (`smart-match` موجودة وجاهزة).
5. **RAG على `knowledge_base`** — الأسعار والأسئلة الشائعة من قاعدة البيانات مش من ذاكرة النموذج.

### المرحلة 3 — تجربة "خرافية" ✨ (أسبوع)

| البند | الوصف |
|------|-------|
| ⚡ **Streaming** | رد متدفق كلمة كلمة (SSE من الـ Edge Function) بدل الانتظار الكامل |
| 🎙️ **صوت حقيقي** | تسجيل → Whisper/ Gemini STT → نص، ورد المساعد بـ TTS عربي اختياري |
| 📷 **تحليل صور ذكي** | ضغط تلقائي، رفع Storage، تحليل بصري حقيقي، وتمييز "صورة غير واضحة" |
| 🃏 **Action Cards** | كروت تفاعلية: تأكيد حجز فني، اختيار وقت زيارة، تقييم الفني — من جوه الشات |
| 👍👎 **Feedback** | تقييم على كل رسالة مساعد + سؤال "إيه اللي ناقص؟" عند 👎 |
| 🔔 **استباقية** | لو عندك طلب نشط يوصلك إشعار "عايز تتبعه؟" يفتح الشات بسياق الطلب |
| 📊 **لوحة تحليلات** | شاشة admin: نسبة الرضا، توزيع النوايا، معدل fallback، أكثر الأعطال تكراراً |
| 🔌 **Fallback محلي ذكي** | لو الـ AI وقع: قاعدة أعطال محلية (JSON) بردود مفيدة بدل "تعذر الاتصال" |
| 🧪 **اختبارات** | widget tests للشاشة + unit tests للـ notifier + golden tests للكروت |

## 📋 البيانات المطلوبة من Supabase عشان نبدأ صح

> ابعتلي أي حاجة متوفرة من دول (export SQL أو screenshots من الـ Dashboard):

1. **Schema الجداول الحالية:** `orders`, `technicians`, `clients` (أو `profiles`) — خصوصاً الأعمدة اللي الموديلات بتستخدمها (`tracking_code`, `status`, `visit_price`, `rating`...).
2. **جدول أسعار الخدمات** لو موجود (ولو مش موجود هنصممه في `knowledge_base`).
3. **مفاتيح الـ AI المُعدّة حالياً** في Supabase Secrets (مش القيم — بس: هل `AI_GATEWAY_API_KEY` / `GEMINI_API_KEY` / `OPENAI_API_KEY` متسجلين فعلاً؟) — عشان نعرف هل المشكلة الحالية fallback بنسبة 100%.
4. **أمثلة شكاوى حقيقية** من العملاء (رسائل، screenshots، أو حتى وصف منك لأكثر 3-5 شكاوى تكراراً).
5. **الأسئلة الشائعة** اللي العملاء بيسألوها (من واتساب/المكالمات) — هنحولها لـ `knowledge_base`.
6. **حالة `smart-match`**: هل شغالة ومتغطية كل أنواع الخدمات؟ (هنستخدمها في الطوارئ).

## ✅ تعريف النجاح (KPIs)

- ✅ 0 أزرار/ردود سريعة بلا handler (تُفحص تلقائياً في المراجعة).
- ✅ نسبة الردود المفيدة (👍) ≥ 80% من تفاعلات الشات.
- ✅ معدل fallback (تعذر الاتصال) < 5%.
- ✅ كل محادثة محفوظة وقابلة للاسترجاع بعد إغلاق التطبيق.
- ✅ طلب الطوارئ من الشات ينشئ طلب فعلي في < 3 ضغطات.
- ✅ زمن أول رمز في الرد (streaming) < 2 ثانية.
